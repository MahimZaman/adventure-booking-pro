# Technical debt

Findings come from code inspection. The priorities reflect the consequences for bookings and operations. No runtime security testing or dependency advisory scan was performed.

| Priority | Finding and source evidence | Recommended change |
| --- | --- | --- |
| High | The summary calculates a fee from metadata, but [ABP_WooCommerce::handle_booking_form](../includes/class-abp-woocommerce.php) reads the final fee from POST, defaulting to zero. `update_cart_item_price()` applies it. Option, time, date, party size and required pickup are also trusted on submission. | Use one server-side validator and price calculator for summary and submission. Resolve a published adventure and allowed option/time, validate dates and counts, and compute the fee from authoritative rates before adding the product. |
| High | [ABP_Ajax::load_booking_summary](../includes/class-abp-ajax.php) reads metadata for a supplied post ID without a post type/status check and prints option title, description and keys directly into HTML or attributes. The [form](../includes/class-abp-shortcodes.php) prints group size into attributes and the [cart name filter](../includes/class-abp-woocommerce.php) concatenates title and location into HTML. Risk depends on who can write those fields and downstream rendering. | Scope public reads to published adventures. Escape text, attributes and URLs for their output contexts. Explicitly allow only intended description markup. Validate group size as an integer. |
| High | [ABP_WooCommerce::ensure_dummy_booking_product](../includes/class-abp-woocommerce.php) runs at `init` and can instantiate `WC_Product_Simple` without a dependency guard. Rendering a matching summary calls `wc_price()`. | Detect missing WooCommerce before hooking dependent code and give administrators an actionable message. |
| Medium | [ABP_WooCommerce::handle_booking_form](../includes/class-abp-woocommerce.php) changes cart state on any frontend POST with the general field `adventure`. No form-specific intent or request-origin check is present. [ABP_Ajax](../includes/class-abp-ajax.php) reads POST offsets without presence/type checks or unslashing. | Introduce a dedicated submission discriminator and appropriate CSRF protection for the guest-capable cart flow. Validate request shape on both paths and return clear errors. Keep public quote access scoped to public data. |
| Medium | [Public JS](../assets/public/script.js) calls `Object.values(jsonRanges)` even when the form is absent. Global IDs/selectors assume one instance. Concurrent summary requests can replace newer selections with older results, and Book Now remains available while a quote loads. | Initialize per form only when present, scope selectors, cancel or ignore superseded responses, and enable submit only for a complete selection. |
| Medium | The [shortcode](../includes/class-abp-shortcodes.php) initially sets only the adult maximum. The [JS change handlers](../assets/public/script.js) calculate the child maximum from an already adjustable adult maximum. UI limits may be missing or inconsistent. Disabled/empty choices do not prevent submission server-side. | Derive both maxima from one immutable party limit, initialize both controls, and enforce the same constraints on submission. |
| Medium | JS compares local datepicker dates with `new Date()` values parsed from date-only strings. `abpFormatDate()` uses local accessors. PHP independently parses dates/times with `strtotime()`. Empty/invalid fields receive no explicit rejection. | Compare validated calendar dates in one declared time zone and test both range boundaries across time zones. |
| Medium | [ABP_WooCommerce](../includes/class-abp-woocommerce.php) reuses any published product at the saved ID. Provisioning has no concurrency guard and submission ignores the result of `add_to_cart()`. The line is sold individually and has a per-submission key. | Verify product ownership/properties, handle creation and cart failures, and define intended repeated-submission behavior. Check multiple bookings with the installed WooCommerce version. |
| Medium | [ABP_Ajax](../includes/class-abp-ajax.php) can emit a fee without a matching option. Pickup times use timestamp-based element IDs across options. Labels are nested, radio inputs are hidden, and the [traveller controls](../includes/class-abp-shortcodes.php) use clickable spans. | Return an explicit unavailable state, generate unique IDs per form and option, and use keyboard-operable buttons and accessible radio groups. |
| Maintenance | [ABP_Public](../includes/class-abp-public.php) loads frontend assets site-wide, versions JS with `time()`, and enqueues the datepicker separately while declaring only jQuery as the script dependency. The [script](../assets/public/script.js) assigns jQuery to global `$`. Theme CSS is pinned to jQuery UI 1.13.2 on a CDN, while the JS version comes from WordPress. | Scope initialization, use stable asset versions, declare the actual script dependencies and isolate the jQuery alias. Review the CSS pin against the deployed datepicker. The repository provides no evidence of installed dependency versions or known vulnerabilities. |
| Maintenance | [ABP_Shortcodes::booking_form](../includes/class-abp-shortcodes.php) begins output buffering before the missing-post-ID early return. [ABP_Ajax](../includes/class-abp-ajax.php) assumes option rows contain all required keys. | Check context before starting the buffer and validate option structure before rendering. |
| Maintenance | [Admin assets](../includes/class-abp-admin.php) are empty but enqueued. The [i18n file](../includes/class-abp-i18n.php) and [POT](../languages/adventure-booking-pro.pot) are empty. Product/error strings use `my-booking-plugin` and `abp` respectively, and public labels are hardcoded. | Remove unnecessary enqueues, use the declared text domain consistently and generate translations if localization is supported. |

## Operational gaps

The repository contains no metadata editor, tests, dependency manifests, declared compatibility matrix, activation-time rewrite flush or uninstall policy. Configure a metadata writer explicitly and decide who owns product/option cleanup before implementing removal. No code reserves seats or decrements capacity across orders. Treat group size as a party input constraint. A deployment promising departure-level inventory needs a separate reservation design.

The source audit found no explicit TODO or FIXME markers. The issues above follow from reachable code and data flow.
