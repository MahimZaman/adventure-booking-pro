# Adventure Booking Pro

Adventure Booking Pro lets a visitor choose a departure, travellers and a pickup time for an adventure, then adds the booking to a WooCommerce cart. WordPress manages the adventures. WooCommerce handles the cart and checkout. The plugin has no separate booking dashboard, reservation ledger or payment gateway.

The [main plugin file](adventure-booking-pro.php) identifies version `1.0.0`, author Mahim Zaman and text domain `adventure-booking-pro`. Its description is “A professional adventure booking plugin for WordPress.” The version is a source identifier. Available Git history is recorded in the [changelog](CHANGELOG.md).

## Install and configure

1. On a WordPress site, activate WooCommerce and configure a working cart and checkout first. This plugin calls WooCommerce on `init` without checking whether it is active. The header declares no minimum or tested WordPress, WooCommerce or PHP versions.
2. Place the plugin directory under `wp-content/plugins/adventure-booking-pro/` and activate **Adventure Booking Pro** in Plugins. On `init`, the plugin creates a published, catalog-hidden, virtual WooCommerce product if the ID in `abp_product_id` does not identify a published product. There is no build or migration step.
3. Open **Adventures → Add New**. Give the adventure a title and publish it. The type also supports a featured image and the built-in category taxonomy.
4. Supply the adventure's post metadata using site-owned tooling or WordPress's `update_post_meta()` API. The repository contains neither a field editor nor an import or field-group definition. Configure the following keys on the adventure itself.

| Post meta key | Expected value and use |
| --- | --- |
| `adventure_options` | An array of option arrays, each with `title`, `description`, `departure_date_start`, `departure_date_end` and `pick_up_times`. Use calendar strings such as `2030-06-01` and comma-separated times such as `09:00,14:30`. |
| `group-size` | Positive whole-number party limit used by the browser controls. |
| `pricing_type` | `individual` displays per-person rates. `group` charges one adult rate for the party. |
| `price_per_adult`, `price_per_child` | Numeric rates formatted in the WooCommerce currency. The child rate applies to per-person pricing. |
| `pickup_location_box` | Set to `allow` to show a required free-text pickup field. |
| `location` | Adventure location displayed beside the map marker in the cart. The visitor's pickup address is stored separately. |

5. Render `[abp_booking_form]` once in the current adventure's post context, for example by calling `echo do_shortcode('[abp_booking_form]');` inside the single-adventure theme template's Loop. The shortcode uses `get_the_ID()` and ignores attributes. Placing it on an unrelated page reads that page's metadata. The registered adventure type supports title and thumbnail only. The plugin supplies no single or archive template.

## Visitor experience and interfaces

The datepicker enables dates in the configured inclusive ranges. Changing the date or party size requests matching options and pickup times. The first matching option and its first time are selected in the browser. **Book Now** posts to the current URL and redirects to the WooCommerce cart. The cart shows the adventure name and location where its item-name filter runs. At checkout the plugin copies the booking fields onto the order line.

| Interface | Access |
| --- | --- |
| Shortcode | `[abp_booking_form]`, no supported attributes. No plugin-defined blocks. |
| AJAX | POST to the URL generated by `admin_url('admin-ajax.php')` with `action=load_booking_summary`, `pickUpDate`, `adult`, `children` and `post_id`. Guests and signed-in visitors receive HTML. |
| REST | `show_in_rest` enables the core adventures collection and item interface (default REST paths `/wp/v2/adventures` and `/wp/v2/adventures/<id>` relative to the site's REST root). The plugin registers no custom REST route or REST metadata schema. |
| Admin | Native adventure list and edit screens. No plugin settings page. WooCommerce owns product and order management. |

## Storage, dependencies and permissions

Adventure records, post meta, category relationships and the `abp_product_id` option use WordPress storage APIs. WooCommerce stores the placeholder product, cart session and eventual order items through its own APIs. The plugin creates no tables, cron jobs, custom roles or capabilities. Adventure administration uses the `post` capability type. Both the public summary and cart submission accept guest input. There is no plugin nonce check, and the cart uses the submitted fee without recomputing it. Review the [security and integrity findings](docs/TECHNICAL-DEBT.md) before relying on the booking total.

Frontend assets require WordPress jQuery, jQuery UI Datepicker and a theme that prints enqueued assets. The datepicker stylesheet is fetched from code.jquery.com. A marker SVG is bundled locally. No external booking or mapping service is called.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Error involving `WC_Product_Simple` | Check that WooCommerce is active and loaded. Provisioning runs on ordinary requests. |
| “No options found.” | Confirm the shortcode's current post ID and that `adventure_options` holds a nonempty array. A nonempty array with no matching range produces a hidden fee field with no visible option. |
| Unexpected total or no rate breakdown | Inspect both rate keys and the exact `pricing_type` value. Missing rates cast to zero. An unrecognized type uses the per-person calculation without displaying the breakdown. |
| Calendar or form stops responding | Check for a single form, datepicker availability, valid ranges and browser errors. On pages without the form the global script reads missing range data. |
| “Booking product not found.” or empty cart after submission | Check the stored product ID and WooCommerce cart setup. The form handler redirects without checking whether adding the item succeeded. |
| New adventure URL returns 404 | Check the site's permalink configuration and refresh rewrite rules through Settings → Permalinks if necessary. The plugin has no activation-time rewrite flush. |

## Source and development

`adventure-booking-pro.php` boots the plugin. `includes/` contains registration, form rendering, AJAX and WooCommerce handlers. `assets/public/` contains the interactive form and styles, `assets/images/` the marker, and `assets/admin/` empty enqueued assets. `languages/` contains an empty POT file. HTML templates are embedded in the PHP callbacks.

The repository ships no dependency manifests, build scripts or automated tests. For local checks and hook signatures see the [developer guide](docs/DEVELOPER-GUIDE.md). For storage and request flow see the [architecture](docs/ARCHITECTURE.md). The [feature inventory](docs/FEATURE-INVENTORY.md) distinguishes reachable code, incomplete behavior and deployment questions. The audit used source inspection and PHP syntax checks. Live booking, payment and checkout behavior remain unverified.
